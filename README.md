跨站请求伪造的防护只看了来源后缀，攻击者用子域和空来源就绕过了检查：来源必须与受信名单精确匹配；空来源与缺失来源必须拒绝；跨站请求的简单请求也要校验；来源与目标站同源时放行；不得接受伪造的路径或用户信息；批量校验各请求独立。不变量：同一来源两次判定结果相同；绕过用例（子域、空值、反斜杠）一律拒绝。

## 目标

本仓库实现跨站请求进入业务处理前的来源校验，覆盖来源解析、归一化、受信名单判断、同源判断、来源页判断、校验触发判断、策略检查和批量校验。调用方可以提供 Origin 头，也可以在需要时提供 Referer 头；所有非法输入都按拒绝处理，不把解析异常抛给业务层。

## 接口约定

八个入口分别承担一项判断，返回值都是布尔值、问题列表或逐条结果。来源对象包含协议、主机和端口三个字段。归一化后的字符串使用小写协议与小写主机，默认端口不出现在结果中。

受信名单的每一项都是一个完整来源。判断时协议、主机和端口都要参与比较。

批量入口接收请求序列和策略，返回整体状态与逐条结果。每一条结果都带有请求标识、是否放行和原因，调用方应以逐条结果为准。

## 校验规则

- 空来源、缺失来源、无法解析的来源以及包含用户信息的来源都拒绝。
- 来源包含路径、查询、片段或反斜杠时不视为合法来源。
- 来源页只取来源部分参与比较，路径、查询和片段不影响判断。
- 来源与目标站同源时直接放行，不要求它出现在受信名单中。
- 简单的跨站请求和带凭证的请求都要进入校验，不能按请求方法跳过。
- 策略中出现空名单、过宽通配或不拒绝空来源的设置时，策略检查返回问题。
- 批量校验逐条独立解析，前一条请求的来源不得沿用到后一条请求。
- 对同一个来源重复判断必须得到相同结果。

## 测试
